# Лабораторные 6–7. Реплицируемое хранилище

## Запуск первой сессии

Из корня репозитория подготовьте окружение в PowerShell.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Откройте три окна PowerShell в корне репозитория и выполните по одной команде в каждом окне. A на порту 50051 — единственный лидер. B и C — ведомые реплики.

```powershell
.\.venv\Scripts\python.exe server.py --port 50051 --name A
.\.venv\Scripts\python.exe server.py --port 50052 --name B
.\.venv\Scripts\python.exe server.py --port 50053 --name C
```

В четвёртом окне запишите значение через B, затем прочитайте его через B в обоих режимах.

```powershell
.\.venv\Scripts\python.exe client.py --port 50052 kv-put x one --strategy QUORUM_CP --operation-id write-1
.\.venv\Scripts\python.exe client.py --port 50052 kv-get x --consistency LINEARIZABLE
.\.venv\Scripts\python.exe client.py --port 50052 kv-get x --consistency FOLLOWER_STALE --max-staleness-ms 5000
.\.venv\Scripts\python.exe -m pytest -q
```

## Что проверяется

- Лидер упорядочивает CP-записи. Он подтверждает запись после получения как минимум двух ACK из трёх с учётом собственной реплики. До этого предложенное значение недоступно для чтения. Повтор той же операции с тем же идентификатором возвращает исходный результат.
- B пересылает строгое чтение на A. Для локального чтения B периодически запрашивает у A подтверждённую версию состояния. Возраст отсчитывается от начала последней успешной синхронизации по монотонным часам B. Поэтому даже давно записанное значение можно читать, пока B продолжает подтверждать актуальность своей копии.
- Флаг `is_stale` указывает на ответ из локального снимка ведомой реплики. Он может содержать последнюю версию. Поле `read_timestamp` содержит метку времени прочитанного значения. При превышении `max_staleness_ms` ведомая реплика возвращает `STALE_READ_EXCEEDED`, в том числе для отсутствующего ключа.
- Состояние хранится в памяти. В первой сессии проверяются отказы узлов с фиксированным лидером и без перевыборов. После полного перезапуска кластера данные нужно загрузить заново.
